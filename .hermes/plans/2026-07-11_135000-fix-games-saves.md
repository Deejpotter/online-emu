# online-emu: Fix Missing Games + Save Persistence

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Make the live site `https://emu.deejpotter.com` show the full game library (sourced from R2) and persist SRM/state saves across redeploys.

**Architecture:** The app is a custom Next.js server on Coolify (dockerfile build pack, self-contained clone from GitHub `main`). The game library is seeded from an R2 manifest (`library/manifest.json`, 3,744 games) when `LIBRARY_SOURCE=r2`. Saves (`.srm` + `.state`) are written to `GAMES_DIR=/data/games/...` and only survive if `/data` is a persistent volume.

**Tech Stack:** Next.js 15, Coolify v4 (dockerfile build pack), Cloudflare R2 (S3-compatible), Traefik.

---

## Root-cause diagnosis (done)

| Symptom | Cause | Status |
|---|---|---|
| No games listed | `R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` env vars were **missing** in Coolify. `getR2Client()` returned `null` → `ensureLibrary()` fell through to the empty-library fallback (wrote `metadata.json` with `games: []`). | **FIXED** — vars added (see Task 1) |
| Saves don't persist | The current app has **no persistent `/data` volume** (`persistent_storages: None`). Saves written to `/data/games/...` land on the ephemeral container layer → wiped on every redeploy. | **PENDING** — volume must be re-created (see Task 2) |

Code references:
- `src/lib/library-source.ts:18` — `getR2Client()` returns `null` unless all 3 `R2_*` creds present.
- `src/lib/library-source.ts:61-78` — seeds `metadata.json` from `library/manifest.json` only when client is non-null.
- `src/app/api/srm/[gameId]/route.ts:198` — writes SRM to `{GAMES_DIR}/{system}/saves/{profileId}/{id}.srm`.
- `src/app/api/saves/[gameId]/route.ts:82` — writes `.state` files to same tree.
- `GAMES_DIR=/data/games`, `DATA_DIR=/data` (set as Coolify env).

## Task 2: Saves — attach a persistent `/data` volume

**Objective:** Ensure SRM + `.state` saves survive redeploys by mounting a persistent volume at `/data`.

**Why the API failed:** Every volume-create endpoint guessed (`/projects/{p}/volumes`, `/servers/{s}/volumes`, `/teams/{t}/projects/{p}/volumes`) returned **404** on this Coolify v4 instance. The app PATCH with `persistent_storages` returned **422** (not an allowed field). The volume must be created via the **Coolify UI** (or a session with UI access).

**Files:** none (infra only)

**Step 1 (UI): Create + attach the volume**
1. Open `coolify.deejpotter.com` → project `online-emu` → app `online-emu`.
2. Go to **Storage / Volumes** → **Add Volume**.
3. Set:
   - Name: `online-emu-data`
   - Mount path (container): `/data`
   - Driver: `local` (bind mount)
   - Host path: `/data/online-emu` (or let Coolify auto-generate a named volume)
4. Save. This recreates the persistent `/data` the app expects.

**Step 2: Redeploy**
```bash
# same start?force=true call as Task 1 Step 2
```

**Step 3: Verify volume is mounted**
```bash
C=$(docker ps --filter "label=coolify.applicationUuid=$APP" --format '{{.Names}}' | head -1)
docker inspect -f '{{json .Mounts}}' $C | python3 -m json.tool   # expect a /data mount with a stable Source
docker exec $C sh -c 'touch /data/_persist_test && echo ok'
# redeploy again, then:
docker exec $C sh -c 'test -f /data/_persist_test && echo PERSISTED || echo LOST'
```
Expected: `PERSISTED` (file survives a redeploy).

**Step 4: Verify a save round-trips**
- In the UI, open a game, play, trigger a save (SRM via `/api/srm/[gameId]` or state via `/api/saves/[gameId]`).
- `docker exec $C sh -c 'find /data/games -name "*.srm" -o -name "*.state" | head'` → expect at least one file.
- Reload the game / redeploy → the save should still load.

## Risks / open questions

- **Volume API blocked:** If the Coolify UI also can't create the volume (rare), fall back to a named Docker volume created directly on the host (`docker volume create online-emu-data`) and attach via the app's raw docker-compose override — but the UI path is the supported one.
- **Public DNS:** The `localhost:443` tunnel check mirrors Cloudflare; if `emu.deejpotter.com` doesn't resolve publicly that's a separate Cloudflare-tunnel publicity step, not a code issue. The app itself serves 200.
- **Pre-existing test failure:** `EmulatorContent.messages` "Hide controls" test fails on clean `main` (unrelated to this work) — leave as-is unless separately scoped.
- **Saves from before this fix are lost:** Any saves made while `/data` was ephemeral are gone. After the volume is attached, new saves persist.
